zudo-docはzfbのzudo-windコンパイラーと**緻密なトークン戦略**を使用します。値は通常のCSSカスタムプロパティで定義し、パッケージのプリセットで対応するユーティリティトークンを登録します。このリファレンスの対象は整合したzfb 4.3.0ファミリーです。

<span id="タイトトークン戦略" />

## 緻密なトークン戦略

スキャフォールドは公開パッケージCSSをインポートし、通常のCSSで値を上書きします。

```css title="src/styles/global.css"
@layer zw-reset, zd-flow;
@import "@takazudo/zudo-doc/theme.css";
@import "@takazudo/zudo-doc/content.css";
@import "@takazudo/zudo-doc/page-loading.css";
@import "@takazudo/zudo-doc/features.css";

:root {
  --font-sans: "Inter", system-ui, sans-serif;
}
```

`theme.css`はカスタムプロパティと、手書きの`@layer base`リセット補正を提供します。プリセットは`reset: "owned-v1"`を選択します。zudo-windのリセットにパッケージの補正を加える構成であり、Tailwindのリセットとバイト単位で同一ではありません。このCSSエントリーではTailwindのインポート、`@source`、safelist CSS、`@theme`による登録を使いません。

<span id="利用できるtailwindの語彙" />

## 使用できるユーティリティの語彙

`text-caption`、`bg-accent`、`px-hsp-md`、`w-icon-sm`、`z-modal`など、プロジェクトの名前付きトークンを使用します。`flex`、`hidden`、`grid-cols-3`などの構造ユーティリティや、対応する明示的な長さ`m-[13px]`も利用できます。Tailwindのすべての綴りに対応しているわけではありません。

プリセットは`spacingUnit`を指定しません。`p-4`などゼロ以外の数値スペーシングに暗黙の0.25remスケールはありません。名前付きスペーシングか角括弧内の明示的な長さを使います。ゼロと`px`は利用できます。`bg-blue-500`などのデフォルトパレット名は登録されません。名前付きgroup/peer、peer-checked、ring、animationには通常のCSSを記述します。

パッケージのクラスは公開`@takazudo/zudo-doc/wind.json`マニフェストで宣言されます。プロジェクトのクラスはzfbのスキャナーが検出できる形で記述します。新しいセマンティックユーティリティは`zudoDoc({ wind })`で登録します。カスタムプロパティの定義だけではユーティリティは増えません。

```ts title="zfb.config.ts"
import { defineConfig } from "@takazudo/zfb/config";
import { zudoDoc } from "@takazudo/zudo-doc/config";

export default defineConfig(
  zudoDoc({
    siteName: "My Docs",
    wind: {
      tokens: {
        colors: { brand: "var(--project-brand)" },
      },
    },
  }),
);
```

```css title="src/styles/global.css (after package imports)"
:root {
  --project-brand: var(--zd-accent);
}
```

zfbはこの上書きをプリセットへ深くマージし、ほかのパッケージトークンを保持します。`wind: false`は生成を明示的に無効にします。外観の切り替えには引き続き`html[data-theme]`とカスタムプロパティを使い、`dark: false`のため別のdarkユーティリティテーマは作りません。

`pnpm exec zfb wind audit --project-root . --fail-on error`を実行します。このフラグによりerror診断がコマンド失敗になります。ただし成功しても条件式内のすべてのクラスの検出や、必要なCSSルールの生成を保証しません。このリポジトリでは`pnpm check:package-wind-manifest`も実行し、代表的なページの生成CSSとcomputed valueを確認します。

## スペーシング

zudo-docではスペーシングを**水平（hsp）**と**垂直（vsp）**の2軸に分離しています。レイアウトにおいてそれぞれ異なる役割を果たすためです。水平スペーシングはインラインのリズムやガターを制御し、垂直スペーシングはコンテンツの流れやセクション間の余白を制御します。垂直スケールは大きいサイズほど広がり、コンテンツにより多くの余白を与えます。

### 水平スペーシング（hsp）

| トークン | 値 | 使用例 |
|-------|-------|---------------|
| `hsp-2xs` | `0.125rem` (2px) | `px-hsp-2xs` |
| `hsp-xs` | `0.375rem` (6px) | `px-hsp-xs` |
| `hsp-sm` | `0.5rem` (8px) | `gap-x-hsp-sm` |
| `hsp-md` | `0.75rem` (12px) | `px-hsp-md` |
| `hsp-lg` | `1rem` (16px) | `px-hsp-lg` |
| `hsp-xl` | `1.5rem` (24px) | `px-hsp-xl` |
| `hsp-2xl` | `2rem` (32px) | `px-hsp-2xl` |

### 垂直スペーシング（vsp）

| トークン | 値 | 使用例 |
|-------|-------|---------------|
| `vsp-3xs` | `0.25rem` (4px) | `py-vsp-3xs` |
| `vsp-2xs` | `0.4375rem` (7px) | `py-vsp-2xs` |
| `vsp-xs` | `0.875rem` (14px) | `py-vsp-xs` |
| `vsp-sm` | `1.25rem` (20px) | `gap-y-vsp-sm` |
| `vsp-md` | `1.5rem` (24px) | `py-vsp-md` |
| `vsp-lg` | `1.75rem` (28px) | `py-vsp-lg` |
| `vsp-xl` | `2.5rem` (40px) | `py-vsp-xl` |
| `vsp-2xl` | `3.5rem` (56px) | `py-vsp-2xl` |

両軸とも`0`（`0px`）と`px`（`1px`）のユーティリティ値も含まれます。

```html
<!-- Horizontal padding + vertical padding -->
<div class="px-hsp-lg py-vsp-md">Content with asymmetric spacing</div>

<!-- Grid with dual-axis gaps -->
<div class="grid gap-x-hsp-md gap-y-vsp-lg">Grid items</div>
```

<Tip>

`hsp-lg`は`1rem`ですが`vsp-lg`は`1.75rem`と、垂直軸は大きいサイズほど広がります。これは意図的な設計です。垂直方向の流れには水平方向のリズムより多くの余白が必要です。

</Tip>

## カラー

カラーは**3層戦略**を採用しています。生のパレット値（Tier 1）がセマンティックトークン（Tier 2）に流れ込み、さらにコンポーネントスコープのトークン（Tier 3）に供給されます。各層は上の層のみを参照するため、カラースキームを切り替えるとサイト全体が一括で更新されます。

カラートークンシステム、カラースキーム、カスタマイズの詳細は[カラーリファレンス](./color.mdx)を参照してください。

## 別の `@theme` との共存

ホスト側の別のTailwindビルドが`@theme`を使う場合も、zudo-docのエントリーでは通常の`:root`プロパティとzudo-windのトークン設定を使用します。ホスト側は別の名前空間を使ってください。zudo-docは23個の名前空間なし`--color-*`エイリアスと`--color-zd-*`接頭辞を予約しています。これらを再定義すると、CSSの生成元にかかわらずパッケージのクロームに影響します。

プロジェクトの上書きより前に`@takazudo/zudo-doc/theme.css`をインポートします。パレットリセットや`theme-no-reset.css`の選択肢はありません。既存の`--color-zd-*`エイリアスはwindのカラートークンとして登録されています。生の`--zd-*`プロパティはカラースキームプロバイダーが所有します。複数のCSSを共有するページでは生成ルールと最終的に適用される宣言を確認してください。

## 使用ルール

<Warning title="登録済みトークンを使用する">

カスタムプロパティは値を供給し、wind設定はユーティリティ名を登録します。トークンや手書きクラスを追加したときは生成CSSを確認してください。

</Warning>

### 推奨

```html
<!-- Semantic color tokens -->
<p class="text-fg">Primary text</p>
<div class="bg-surface border border-muted">Panel</div>
<a class="text-accent hover:text-accent-hover">Link</a>

<!-- Spacing tokens -->
<div class="px-hsp-lg py-vsp-md">Proper spacing</div>
<div class="gap-x-hsp-sm gap-y-vsp-md">Grid gaps</div>

<!-- Typography tokens -->
<h2 class="text-title font-semibold leading-tight">Heading</h2>
```

### 非推奨

```html
<!-- DON'T: Tailwind defaults — not defined and produce nothing -->
<div class="p-4 bg-gray-500 text-sm">Broken</div>

<!-- DON'T: Hardcoded hex — breaks theming -->
<div class="bg-[#1e1e2e] text-[#f8f8f2]">Breaks on theme switch</div>
```

デフォルトトークンは `@takazudo/zudo-doc/theme.css` から提供され、`packages/zudo-doc/src/theme.css` が唯一の情報源です。scaffold の `src/styles/global.css` はそれらのデフォルトをインポートし、プロジェクトの上書きポイントを提供します。

## インタラクションのルール

### リンク要素にホバー時の下線を使う

_遷移する_ 要素（`<a href>`、またはリンクとして振る舞う要素）は、ホバー時とキーボードフォーカス時にアンダーラインを表示します。ボタン、トグル、コントロールは対象外で、ボーダー／背景の変化で代替します。

**OK**（ナビゲーション用のリンク）：

```html
<a class="text-accent hover:underline focus-visible:underline">Link</a>
<a class="text-fg hover:text-accent hover:underline focus-visible:underline">Sidebar item</a>
```

**NG**（focus-visible が欠けている）：

```html
<!-- DON'T: mouse users get an underline, keyboard users don't -->
<a class="text-fg hover:underline">Inaccessible to keyboard focus</a>
```

**NG**（コントロール）：

```html
<!-- DON'T: buttons use border/bg hover, not underline -->
<button class="hover:underline">Use hover:bg-accent/10 instead</button>
```

`hover:underline focus-visible:underline` のペアが正規形です。必ず両方を書き、片方だけにはしないでください。実装例：`packages/zudo-doc/src/header/header.tsx`、`src/components/site-tree-nav.tsx`、`packages/zudo-doc/src/footer/footer.tsx`。

より深い背景（ライト／ダークのコントラスト、下線だけで足りるか色の変化も必要か）は、ローカルの `/css-wisdom` スキルを参照してください。light-mode/dark-mode と three-tier トークン戦略のセクションがトレードオフを扱っています。
