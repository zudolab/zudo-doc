## 概要

`create-zudo-doc`でプロジェクトをスキャフォールドすると、2つの独立したオプションによって、厳選された`zudo-doc-*` [Claude Codeスキル](https://docs.anthropic.com/en/docs/claude-code/skills)がプロジェクトの`.claude/skills/`ディレクトリに同梱されます：

- **Claudeスキル（ユーザー向け）** — 執筆・保守用スキル：zudo-doc自身の規約に従ってデザインシステムの編集、ドキュメントの翻訳、リリースの作成を支援します。
- **Claudeスキル（ライティング）** — AIエージェントにドキュメントの書き方とナビゲーション構造の正しい設計方法を教える、単一のライティングガイドスキルです。

これらは生成されたドキュメントではなく、実際に動作するスキルです。各スキルは自己完結した`SKILL.md`で、`create-zudo-doc`パッケージ自体の中でスキャフォールド向けのバリアントとして管理されており（zudo-docリポジトリからそのままコピーされたものではなく、生成プロジェクトのレイアウトに合わせて書き直されています）、プロジェクト内で開いたClaude Codeセッションでスラッシュコマンドとして利用できます。

どちらの機能も**デフォルトで無効**で、それぞれ独立して有効化できます — スキャフォールド時に片方だけ、両方、あるいはどちらも選ばないことができます。

<Info>

これは、リソースディレクトリからドキュメント**ページ**を自動生成する[Claude Codeリソース](./claude-resources.mdx)（およびCodex版の[Codexリソース](./codex-resources.mdx)）や、ドキュメントを参照用スキルに変換する[ドキュメントスキルシンボリックリンカー](./doc-skill-symlinker.mdx)とは異なります。Claudeスキル機能は、既製のスキルをプロジェクトに**同梱します**。

</Info>

## Claudeスキル（ユーザー向け）

**Claudeスキル（ユーザー向け）**を有効にすると、3つのスキルがスキャフォールドされたプロジェクトの`.claude/skills/`にコピーされます：

| スキル | 目的 |
|-------|------|
| `zudo-doc-design-system` | プロジェクト固有のCSSおよびコンポーネントルール — デザイントークン、三層カラーアーキテクチャ、コンポーネントファースト戦略。CSS、Tailwindクラス、カラートークン、コンポーネントマークアップを編集する前に参照します。 |
| `zudo-doc-translate` | `zfb.config.ts`で設定したロケール間でドキュメントを翻訳します。zudo-docの日本語規約は`ja`にだけ適用します。 |
| `zudo-doc-version-bump` | パッケージバージョンの更新、changelogドキュメントの生成、コミット、タグ付け、GitHubリリースの作成を行います。 |

`create-zudo-doc`の対話型プロンプトで**Claudeスキル（ユーザー向け）**を選択するか、CLIフラグを渡します：

```bash
pnpm create zudo-doc my-docs --claude-skills
```

### その他に設定されるもの

`zudo-doc-version-bump`はリリースフローの一部として`<パッケージマネージャー> b4push`を実行するため、この機能を有効にすると、新しいプロジェクトでスキルが「スクリプトが見つからない」エラーで失敗しないように、生成される`package.json`に最小限の`b4push`スクリプトも追加されます：

```jsonc
{
  "scripts": {
    "b4push": "pnpm check && pnpm build"
  }
}
```

これは意図的に小さなスタブ — 型チェックの後にビルドを行うだけ — です。後でより充実したプッシュ前パイプラインに拡張するのは自由です。

## Claudeスキル（ライティング）

**Claudeスキル（ライティング）**を有効にすると、1つのスキルがスキャフォールドされたプロジェクトの`.claude/skills/`にコピーされます：

| スキル | 目的 |
|-------|------|
| `zudo-doc-writing` | ドキュメント執筆とナビゲーション構造のガイド — ナビゲーションツリーを先に計画するワークフロー、3階層ナビゲーション、ファイル構造＝ナビゲーションの原則、カテゴリインデックスページ、`sidebar_position`の徹底、フロントマタースキーマ、h1禁止ルール、相対`.mdx`リンク、アドモニション構文。 |

このスキルが存在するのは、ガイドなしで「ドキュメントを書いて」と頼まれたAIエージェントが、ほぼ確実に混沌としたナビゲーション構造を作ってしまうためです — ページが手近な場所に放り込まれ、カテゴリのランディングページがなく、サイドバーがアルファベット順に並ぶ、という状態です。このスキルは[ドキュメントの書き方](../getting-started/writing-docs.mdx)と[ナビゲーションの構成方法](../getting-started/structuring-navigations.mdx)のガイドを、エージェントがページを作成・編集する前に参照するルールに凝縮しており、生成されるドキュメントサイトを確実に良い形に保ちます。

対話型プロンプトで**Claudeスキル（ライティング）**を選択するか、CLIフラグを渡します：

```bash
pnpm create zudo-doc my-docs --claude-skills-writing
```

<Tip>

ドキュメントの大部分をAIエージェントに書かせる予定なら、この機能を有効にしてください — そして、ページを作成する前に`/zudo-doc-writing`を呼び出すようエージェントに指示してください。ナビゲーション計画のステップはエージェントが最も省略しがちで、かつ最も重要な部分です。

</Tip>

## スキルの使用

スキャフォールド後、プロジェクトをClaude Codeで開き、スラッシュコマンドとしてスキルを呼び出します。たとえば、スタイルに手を加える前に：

```
/zudo-doc-design-system colors
```

あるいは、ドキュメントを書く前に：

```
/zudo-doc-writing
```

Claudeはルールを読み込み、変更に適用します。他のスキルも同様に、必要なときに名前で呼び出します。

<Tip>

同梱されたスキルはプロジェクトの`.claude/skills/`に配置され、自由に編集できます。出発点として扱い、チームの働き方に合わせて規約を調整してください。

</Tip>
