## 概要

`agentExport`を有効にすると、現在のドキュメントを静的なエージェント向けファイルとして公開できます。Cloudflare、MCPサーバー、データベース、AIプロバイダーは不要で、どの静的ホストでも利用できます。新規プロジェクトでは選択しない限り無効です。名前付きの`search`と`fetch`ツールで接続する場合は[MCPサーバー](./mcp-server.mdx)を参照してください。

## エクスポートを有効にする

イニシャライザーで「Agent export」を選ぶか、プロンプトを使わずに生成します。

```bash
pnpm create zudo-doc my-docs --agent-export --yes
```

既存プロジェクトでは、`zfb.config.ts`の`zudoDoc({ ... })`に`agentExport: true`を追加し、再ビルドします。

```ts title="zfb.config.ts"
export default defineConfig(
  zudoDoc({
    siteUrl: "https://docs.example.com",
    agentExport: true,
  }),
);
```

安定した絶対URLを引用に使えるよう、公開サイトの`siteUrl`を設定してください。空の場合、成果物とページのURLは`base`付きのパスになることがあります。MCPサーバーはリクエスト元のオリジンで解決できます。エクスポートには設定済みの`base`が適用されます。

既存サイトから削除するには、`agentExport: false`にするかフィールドを削除し、再ビルド・再デプロイします。以前アップロードしたファイルを保持するホストでは、古い`/agent/v1/`ファイルも削除してください。`mcp: true`も設定している場合は、先にMCPを無効にします。

## 公開されるファイル

現在のビルドは、設定した`base`の下に次のバージョン付き構成を書き出します。

```text
<base>/agent/v1/manifest.json
<base>/agent/v1/search-index.json
<base>/agent/v1/items/<item-key>.json
<base>/agent/v1/pages/<page-key>.md
```

`base`が非ルートの場合、ファイルは`dist/<base>/agent/v1/`に書き出されます。デプロイで`dist/`全体を`base`配下へ移動するために`copyPublicWithBase: false`を設定している場合は、二重のパスにならないよう`dist/agent/v1/`に書き出されます。移動後は`<base>/agent/v1/`で配信され、`llms.txt`とマニフェストのURLもそのまま解決できます。

エクスポートは常に`public/`からコピーされたファイルと同じ場所に置かれます。アップロードした`dist/`を`<base>/`で配信する一般的な静的ホストでは、`copyPublicWithBase: false`を設定して、publicのファイルとエクスポートをHTMLページと同じ階層に置きます。これは`zudoDoc()`の設定ではなくzfbのオプションなので、展開した呼び出しの横に書きます。`zudoDoc({ ... })`の中に書いても効果はなく、`zfb check`が未知のプロパティとして報告します。`zfb preview`はこの移動を再現しないため、この設定ではbase付きのpublicファイルとエクスポートがプレビューで404になります。移動後のレイアウトで確認してください。

```ts title="zfb.config.ts"
export default defineConfig({
  ...zudoDoc({
    base: "/handbook",
    agentExport: true,
  }),
  copyPublicWithBase: false,
});
```

`manifest.json`にはサイト、言語、コンテンツのフィンガープリント、文書、取得項目、人が読むページのURL、成果物のURLが含まれます。`search-index.json`にはブラウザー検索とは独立して、正規化された項目の全文が入ります。各項目ファイルには`id`、`title`、`text`、`url`、`metadata`があり、メタデータは言語、親ページ、フィンガープリント、1から始まる分割番号と総数を示します。ページの`.md`ファイルには正規化された本文全体が入ります。長いページは取得可能な複数の項目に分割され、本文が黙って切り捨てられることはありません。項目IDは生成されたキーであり、ソースパスではありません。

フィンガープリントは同一ビルドの整合性を示すもので、改訂履歴ではありません。公開中の変更履歴ページは通常のコンテンツです。`draft`、`unlisted`、`search_exclude`、およびルートを持たない`category_no_page`ページは対象外です。実体のある各言語の文書だけを書き出し、言語フォールバックから複製は作りません。ビルド時の正規化では、文章、見出し、リンク、画像、表、注記の本文、コードを残します。表現できない動的MDXは、リクエスト時に実行せず、未対応であることを明示します。相対リンクは元のページを基準に解決されます。引用には人が読むページのURLを使ってください。

## 静的ホスティングとアクセス

通常どおり生成した`dist/`を公開します。クライアントはマニフェストとMarkdownを直接読むか、[llms.txt](./llms-txt.mdx)をブラウザーで明示的に開けます。これらの形式を置くだけで、すべてのAIクライアントが自動的に発見するわけではありません。

zudo-docはファイルを書き出すだけで、ホストのレスポンスヘッダーは設定しません。多くのホストは`.md`をMarkdownとして配信しますが、`text/plain`や`application/octet-stream`で送ったり`charset`を付けなかったりするホストもあり、日本語などの非ASCII文字が化けることがあります。その場合は`<base>/agent/v1/pages/*.md`に`Content-Type: text/markdown; charset=utf-8`を送るようホストを設定してください。JSONファイルにはJSONのメディアタイプが必要です。Cloudflareでは[静的アセットのヘッダー](./mcp-server.mdx#検出用ドキュメント-cloudflareでの静的アセット用ヘッダー（任意）)を参照してください。

各ページには別々のURLが二つあります。人が読むページは常にHTMLを返し、そのMarkdownは専用の`.md`のURLを持ち、ページの`<link rel="alternate" type="text/markdown">`からリンクされます。`Accept`ヘッダーでレスポンスが変わることはないため、エクスポートに`Vary: Accept`は不要で、通常の閲覧も変わりません。

### 関連する機能

- **このエクスポート**: zudo-docがビルド時に生成する任意のMarkdownとJSONファイルで、どの静的ホストでも配信できます。
- **[MCPサーバー](./mcp-server.mdx)**: このエクスポートを対象に`search`と`fetch`ツールを提供する、別に有効化するエンドポイントです。リクエスト時に動くデプロイが必要ですが、静的エクスポートには不要です。
- **Cloudflare Markdown for Agents**: ページのURLへのリクエストが`Accept: text/markdown`を求めたときに、CloudflareのエッジでHTMLをMarkdownに変換するCloudflareのサービスです。zudo-docではなくCloudflare側で設定するもので、このエクスポートに必要でもなく、このエクスポートが提供するものでもありません。

これは**公開コーパス**です。`robots.txt`、`noindex`、`unlisted`、`search_exclude`は公開範囲を調整するもので、認証ではありません。保護された文書には有効にしないでください。将来の保護付きデプロイでは、`/mcp`だけでなく同等の静的成果物すべてを保護する必要があります。取得した文書は信頼できない資料として扱い、コマンドの実行やツール権限の拡大を指示するものとして扱わないでください。
