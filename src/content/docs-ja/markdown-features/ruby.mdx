`ruby` 機能は CJK テキストに読み仮名（ルビ）注釈を追加し、インライン構文を標準の HTML `<ruby>` マークアップへと描画します。

:::danger[zfb next.13 では既知のブロック]

ルビ注釈構文は、現在 zfb `0.1.0-next.13` で **SSR レンダリングが 500 を返します**。zudo-doc の `zfb.config.ts` では**無効化**されており、このページでは実例なしで解説します — 以下の構文はフェンスコードブロック内にのみ記載されています。アップストリームで [#1815](https://github.com/zudolab/zudo-doc/issues/1815) として追跡されています。アップストリームのクレートが修正され次第、このページにライブデモを追加します。

:::

## 設定

アップストリームの問題が解決されたら、`ruby` キーで機能を有効化します。`true` のショートハンドを受け付けます。

```ts title="zfb.config.ts"
export default defineConfig({
  markdown: {
    features: {
      ruby: true,
    },
  },
});
```

## 構文

注釈は、ベーステキストの直後にキャレットと波括弧で読みを記述する形式です — `{base}^{ruby}`:

```md
漢字^{かんじ}を学^{まな}ぶ
```

## 期待される HTML 出力

この機能は、注釈を意味のある `<ruby>` マークアップとして描画することを意図しています。

```html
<ruby>漢字<rt>かんじ</rt></ruby>を学<rt>まな</rt>ぶ
```

## ブロックの理由

next.13 での隔離プローブにより、単一のルビ注釈を含むページは SSR レンダリングで汎用的な 500 エラーを起こす一方、注釈以外は同一の対照ページ（注釈なし）は問題なくビルドできることが確認されました。この失敗は zfb の Rust 側ルビパス内部で発生しており、`<Ruby>` コンポーネントの欠如が原因では**ありません**。そのためコンポーネントのスタブを登録しても修正されません。安全に記述できるライブ構文が存在しないため、アップストリームの修正が入るまでこの機能は無効のままとします。

## スコープ

この機能は明示的な `{base}^{ruby}` 構文のみを解析します。漢字の自動検出や形態素解析によるふりがなの自動付与は行いません — これは意図的にスコープ外としています。
