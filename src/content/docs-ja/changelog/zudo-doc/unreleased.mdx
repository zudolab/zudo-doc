### バグ修正

- `gen:changelog` が、括弧で囲まれたリンクタイトルにも対応しました。出力対象のエントリへのリンクを書き換える際はタイトルを保持し、それ以外の相対ドキュメントリンクを外す際はタイトルも削除します。エントリ本文の1行の Setext 見出しも GitHub アンカーの連番に数えるようになり、後続の同名バージョン見出しへのリンクが正しい位置を指すようになりました。ファイル名の大文字・小文字は引き続き区別するため、`.MDX` のリンクは `.mdx` のエントリに解決されません。（#4338）
- サイト名が長い状態でブラウザのフォント設定を大きくすると（例: 390px 幅・24px 指定）、ヘッダー右側のコントロール群（検索、AI アシスタント、デザイントークンパネル、GitHub リンク）が画面幅からはみ出してモバイルで操作できなくなる問題を修正しました。サイト名のリンクが縮まずにいたことが原因で、これを省略記号（ellipsis）付きで縮小できるようにし、省略された全文は `title` 属性から参照できるようにしています。あわせてモバイルのハンバーガーボタンも縮まないように固定してあります（ヘッダーを自作してこのボタンを直接並べた場合に、サイト名の代わりに潰れてしまわないようにするためです）。デフォルトのフォントサイズや、通常の長さのサイト名では従来どおり全文がそのまま表示され、影響はありません。（#4287, #4288, #4289）
- `designTokenPanel` をオフにしたまま `@takazudo/zudo-doc/design-token-panel-bootstrap` から自前のデザイントークンパネルをマウントするホストが、本物の `@takazudo/zdtp` ローダーを維持できるようになりました（これまでは例外を投げるスタブに当たっていました）。5.24.1 の修正（#4201）は `designTokenPanel` がオフのときに `@takazudo/zudo-doc/zdtp-loader` を常にスタブへ差し替えており、そのチェンジログの注記（「ホスト側で独自に書いた `@takazudo/zdtp` のインポートには影響しません」）は、パッケージ自身のブートストラップのサブパス経由で zdtp に到達するホストをカバーしていませんでした — その経路はスタブのまま残り、ビルド自体はグリーンでもパネルを開いた瞬間に例外が発生し得ました。新しい `bundleZdtp?: boolean` 設定は `bundleZdtp ?? designTokenPanel` として解決され、バンドルとマウントを分離します: 未設定のままなら挙動は変わらず、`designTokenPanel: false` と組み合わせて `bundleZdtp: true` にすれば、自前のパネル用に本物のローダーを維持できます。逆の組み合わせ — `designTokenPanel: true` と `bundleZdtp: false` — は設定解決の時点で拒否されます。パッケージのパネルがマウントされているのにローダーがスタブ化されていると、確実に例外が発生するためです。（#4261）
- `gen:changelog` が、公開される`CHANGELOG.md`に相対`.md`／`.mdx`リンクをそのままコピーしてしまう問題を修正しました。同じディレクトリ内の別エントリのソースファイルを指すリンクは、出力時にファイル内アンカーへ書き換えられるようになり、その際リンクに付いていた`#fragment`は削除されます（サブ見出しのテキストはバージョンをまたいで繰り返し使われるため）。それ以外の相対`.md`／`.mdx`リンク——生成済みのエントリに解決できないもの——はリンクを外し、ラベルのテキストだけを残して href を削除します。MDX側のソースは変更不要です——著者はこれまでどおりドキュメントサイト向けの相対リンクを書けばよく、書き換えは生成される成果物にのみ適用されます。（#4312）

### その他の変更

- ビルド失敗の報告（#4267、#4271 で追跡）を調査しました。`@takazudo/zfb@2.18.0` ＋ `@takazudo/zudo-doc@5.25.0` の組み合わせで、pnpm ワークスペース配下の consumer（`pages/` がエラーに挙がったパッケージ注入ルートのいずれも上書きしていない構成）において、`../node_modules/@takazudo/zudo-doc/routes-src/*.tsx` のような相対指定（1階層深いルートでは `../../`）に対する `Could not resolve` の esbuild エラーが3件発生するというものです。報告者の pnpm ワークスペース・シンボリックリンク構成を含む11通りの consumer 構成で再現せず、詳細は `packages/zudo-doc/docs/findings/4267-shadow-tree-probe.md` にまとめています。コードの変更はありません。再現しなかったため、回避策もこちらでは検証できていません。報告者自身の bisect では `@takazudo/zudo-doc@5.24.2` が zfb 2.18.0 で問題なしとされており、また該当する3ルートをローカルの `pages/` ファイルで上書きすれば、生成されるシムは仕組み上バイパスされます。この事象に遭遇した場合は、#4271 に記載の診断情報の添付にご協力ください。
