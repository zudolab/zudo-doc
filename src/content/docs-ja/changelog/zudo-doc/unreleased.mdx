### バグ修正

- モバイルのサイドバードロワーが Escape キーで閉じるようになり、フォーカスがトグルボタンへ戻るようになりました。このドロワーは、ビューポート全体を覆うバックドロップの上に表示され、開いている間は body のスクロールを固定し、閉じている間は `inert` になるモーダル相当のサーフェスです。キーボードのみの利用者や支援技術の利用者が最初に試すのは Escape ですが、`SidebarToggle` アイランドにはキーイベントのハンドラーが登録されておらず、これまでは何も起きませんでした。リスナーはドロワーが開いている間だけ `document` に登録されるため、閉じている状態で言語切り替えやテーマパックのフライアウトなど他のサーフェス宛ての Escape を横取りすることはありません。閉じるのと同時にフォーカスをトグルへ戻しているのは、パネルが再び `inert` になるためで、そのままではドロワー内にあったフォーカスが `<body>` に取り残されてしまうからです。なお、IME の変換確定・取り消しに伴う Escape は無視するため、ドロワー内のフィルター入力で日本語変換をキャンセルしてもドロワーは閉じません。
- ドロワーを開いた状態でトグルの X をクリックすると、ドロワーが閉じるようになりました。開いている間のトグルは閉じるアイコンを表示しているにもかかわらず、バックドロップの下に隠れていました。`z-modal-backdrop`（50）がヘッダーの `z-toolbar`（20）を覆うため、ボタン中央の座標で `document.elementFromPoint()` を呼ぶとバックドロップの要素が返り、実際のポインターイベントはすべて遮られていました。トグルは開いている間だけドロワーと同じ階層（`relative z-modal`、60）へ持ち上がるようになり、アイコンが示すとおり X でドロワーを閉じられます。ヘッダーのそれ以外の要素は引き続きバックドロップの下で暗転し操作できないままで、閉じた状態のマークアップにも変更はありません。上記の Escape 対応と合わせて、キーボードとポインターの両方の閉じ方が揃いました。これらの修正前は、開いたドロワーから抜ける手段がバックドロップのクリックだけで、しかもそれを知る手がかりが UI 上にありませんでした。
