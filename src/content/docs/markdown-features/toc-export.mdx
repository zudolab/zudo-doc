The `tocExport` feature walks a document's headings and injects an MDX named export — `export const toc` — at the top of each processed file, giving sidebar and floating-TOC components a structured table-of-contents.

:::danger[Known-blocked at zfb next.13]

Enabling `tocExport` **breaks the build** at zfb `0.1.0-next.13`: the injected `export const toc = [...]` line is emitted at an indented column, so MDX parses it as content rather than an ESM export, producing ~153 esbuild `Expected "}"` errors across the corpus. It is **not enabled** in zudo-doc's `zfb.config.ts`, and this page documents it without a live demo. Tracked upstream as [#1814](https://github.com/zudolab/zudo-doc/issues/1814). Re-enable once zfb emits the export at column 0.

:::

## Configuration

Once the upstream issue is resolved, enable with defaults (`maxDepth: 3`). It is an object-typed feature, so it must be given an options object:

```ts title="zfb.config.ts"
export default defineConfig({
  markdown: {
    features: {
      tocExport: {},
    },
  },
});
```

Limit the heading depth:

```ts title="zfb.config.ts"
tocExport: { maxDepth: 2 },
```

## Options

| Option | Default | Description |
| --- | --- | --- |
| `maxDepth` | `3` | Maximum heading depth (absolute, 2–6). `2` = h2 only; `3` = h2 + h3. |

## Exported shape

The feature injects an `export const toc` whose entries follow this type:

```ts
type TocEntry = {
  depth: number; // absolute heading depth: 2 | 3 | 4 | 5 | 6
  id: string; // slug assigned by the heading-links pass
  text: string; // plain-text heading content (hash-link stripped)
  children: TocEntry[]; // nested sub-headings within maxDepth
};
```

## Example output

For a document with h2 and h3 headings, the injected export looks like:

```ts
export const toc = [
  {
    depth: 2,
    id: "introduction",
    text: "Introduction",
    children: [{ depth: 3, id: "background", text: "Background", children: [] }],
  },
  { depth: 2, id: "conclusion", text: "Conclusion", children: [] },
];
```

## Notes

- The export runs after the heading-links pass, so the `id` slugs are final and deduplicated.
- `tocExport` works independently of [Heading Marker TOC](./heading-marker-toc.mdx) — enabling one does not interfere with the other.
- zudo-doc's existing TOC island is not driven by this export; the two are separate mechanisms.
