The `ruby` feature adds phonetic ruby annotations for CJK text, rendering an inline syntax to standard HTML `<ruby>` markup.

:::danger[Known-blocked at zfb next.13]

The ruby annotation syntax currently **500s the SSR render** at zfb `0.1.0-next.13`. It is **disabled** in zudo-doc's `zfb.config.ts` and is documented here without a live example — the syntax below appears only inside fenced code blocks. Tracked upstream as [#1815](https://github.com/zudolab/zudo-doc/issues/1815). This page will gain a live demo once the upstream crate is fixed.

:::

## Configuration

Once the upstream issue is resolved, the feature is enabled with the `ruby` key. It accepts the `true` shorthand:

```ts title="zfb.config.ts"
export default defineConfig({
  markdown: {
    features: {
      ruby: true,
    },
  },
});
```

## Syntax

The annotation uses a caret followed by the reading in braces, written immediately after the base text — `{base}^{ruby}`:

```md
漢字^{かんじ}を学^{まな}ぶ
```

## Expected HTML output

The feature is intended to render the annotation as semantic `<ruby>` markup:

```html
<ruby>漢字<rt>かんじ</rt></ruby>を学<rt>まな</rt>ぶ
```

## Why it is blocked

An isolated probe at next.13 confirmed that a page containing a single `^{…}` annotation fails the SSR render with a generic 500, while an otherwise identical control page (no annotation) builds cleanly. The failure originates inside zfb's Rust ruby pass — it is **not** a missing `<Ruby>` component, so registering a component stub does not fix it. Because no live syntax can be authored safely, the feature is left disabled until the upstream fix lands.

## Scope

The feature parses only the explicit `{base}^{ruby}` syntax. It does not perform automatic kanji detection or morphological analysis to assign furigana — that is intentionally out of scope.
