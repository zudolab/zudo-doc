Released: 2026-10-14

### Features

- Adds optional `SidebarDefinition.scopeRoot?: "configured" | "editorial"` (default `"editorial"`, unchanged behavior). `"configured"` caps Broaden, branch focus, Restore, and route reconciliation at the authored forest: empty `items` stop at the category-filtered tree, one `autogenerated` directory stops at that directory, and an explicit list stops at that list. `initialPath` remains the starting view and the Restore baseline. At the cap the scope toolbar is omitted. An unsupported value fails the build. An omitted entry or an array stays editorial. (418b2f29c)

### Bug Fixes

- The shared `tsconfig.base.json` no longer sets `baseUrl`, which TypeScript 7 rejects with TS5102 in every project that extends it. Projects that relied on the inherited `baseUrl` for bare `paths` targets should write them as explicitly relative paths (for example `"@/*": ["./src/*"]`), which TypeScript 5.9 and 7 both resolve against the declaring tsconfig. (4d5e801ed)
- `buildSidebarForSection` now applies `initialPath` and `initialPathMode` to an object sidebar definition with empty `items`, matching `buildSidebarNavigation`. Previously the empty-items case returned the plain category-filtered tree and ignored those options. (31fe01015)
- Updates the lazy browser Mermaid URL from 11.15.0 to the exact 11.17.2 release, including the advisory fixes introduced in 11.16.1. Local npm audit does not cover the separately delivered CDN graph. (76d637663)
- The desktop sidebar and the mobile drawer each keep their scroll offset across client navigation, a full document load, reload, and Back/Forward, including after Broaden. Restoration runs after the destination tree can hold the offset, so a replaced sidebar or a temporary empty tree does not snap back to the top. A saved zero is restored. A missing snapshot is not written as zero. A closed drawer keeps its saved offset in history until it opens again. Article scroll, focus, filtering, and disclosure are left unchanged. (418b2f29c, 2b38ccf0a)
- The Appearance menu is a compact list of three rows (Light, Dark, System). The visible heading and the bottom helper are removed. The System row shows the device's current Light/Dark mode inline, and that status stays truthful while a manual Light or Dark preference is selected. The full localized helper remains the System option's accessible description. The popup is sized from its natural height at its final width, so its border no longer creates a spurious inner scrollbar. It opens above the trigger near the bottom edge and repositions when its content size changes. Opening, arrow keys, and focus return no longer scroll the page, and Tab / Shift+Tab leave the menu instead of cycling its rows. (37e3b8b42, 7aba63e28)

### Other Changes

- Requires zfb 4.5.0: the `@takazudo/zfb`, `zfb-runtime` and `zfb-md-wasm` peer floors move from `^4.3.3` to `^4.5.0`. zfb 4.4.0 updates its YAML frontmatter parser and fixes fragment Back/Forward navigation. zfb 4.5.0 also restores a previously rendered same-path query entry on Back/Forward, fixes sibling radio-group state on form reset, and adds opt-in CSS compiler and `ErrorBoundary` APIs. Upgrade the zfb family (and `zfb-adapter-cloudflare` when used) to 4.5.0 together with this release. (48a224468, 4f9d0c26f)
- Updates the Codex resource TOML parser to smol-toml `^1.9.1`, preserving configuration dates and agent metadata while including its bounded key-scanning fix. (05e3fb5e7)
