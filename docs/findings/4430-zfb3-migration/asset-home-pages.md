## Port decisions and verification

- Asset-viewer leaf modules remain importable without `ChromeContext`, `doclayout/` or `chrome/`; the shared guard now permits only `@takazudo/zfb/zudo-react` and `/jsx-runtime`, rejects Preact and all other zfb subpaths, and is exercised by the source and export-contract tests. The graph walker and declaration helpers themselves are unchanged. The self-test checks the actual doclayout import, then uses an isolated synthetic entry to prove that forbidden package imports are detected without bundling unrelated red-window modules.
- Asset component JSX now uses the public zudo-react spellings. `AssetFileIcon` and all icon call sites accept/pass `class`. Asset page/index body components return `Child`; their data preparation, pure label helpers and asset-tree builder stay framework-free. The `AssetTree` maps remain static intrinsic children because these are generated pages, not reactive island lists.
- `AssetActions` keeps native download behavior by rendering `download=""`; zfb 3.1 requires a string for this overloaded attribute, so the SSR assertion now expects the empty-string form rather than Preact's bare boolean form. The browser still treats the empty attribute value as download-enabled.
- `AssetVideoStage` keeps the v2 `controls` and `preload="metadata"` behavior in a static fragment on its existing `<div>` host. `assetVideoMarkup` escapes `&`, both quote forms and angle brackets in the URL and escapes numeric dimensions before serialization. The ordinary div is a valid parser parent; `rawHtml` has no JSX children, executable payload, nested island marker or update binding. `asset-page-body.test.tsx` includes a URL containing an attempted script injection; `asset-page-ssg.test.tsx` checks the rendered controls/preload/dimensions. This is a tracked workaround for [zfb #3359](https://github.com/Takazudo/zudo-front-builder/issues/3359), still a release blocker on published 3.1.0. The exact TypeScript repro was added as evidence in [upstream comment](https://github.com/Takazudo/zudo-front-builder/issues/3359#issuecomment-5935939559); remove the shell after published JSX declarations and runtime SSR both support native video attributes.
- Other `rawHtml` sites use trusted generated/static values only: `asset-components/asset-code.tsx#createAssetCode` receives syntax-highlight markup produced by the internal asset-viewer highlighter; `asset-page/components.tsx#AssetCodeBody` extracts the generated `<code>` fragment from the pre-highlighted asset record; `asset-page/body.tsx` and `asset-index-page/body.tsx` inject the static controller literals from their `script.ts` modules. Script literals have no `</script` substring and carry no dynamic page input. Each is exclusive with children in an ordinary script or div host; there are no nested islands or child bindings. Existing highlighter tests cover line markup; the focused body/SSG and script suites cover rendering/controller syntax and navigation hooks.
- The homepage keeps the same `HomePageViewProps` and route behavior. Its former keyed `Fragment` separators are a flat `Child[]`; this produces the same `/` separator count without extra DOM. Logo masks use CSS-string `-webkit-mask` and `mask` declarations for [zfb #3375](https://github.com/Takazudo/zudo-front-builder/issues/3375), preserving quoted URL escaping. The `Island({ when: "idle", children })` boundary remains build-identified; isolated SSR tests mock its identity because the red-window source harness does not run the scanner. `AutoLogo`, `CompactProse` and the shared head/layout are isolated at their owned seams in these leaf tests; route-context intro preparation, links, content composition and metadata/layout props remain covered.
- #4440 authored-class review: marker-only `zd-asset-pdf`, `zd-home-hero`, `zd-home-intro`, `zd-home-sitemap` and `zd-home-tags` moved to `data-zd-*` hooks. The consumer-facing e2e selectors outside this topic's file ownership were handed to [#4469](https://github.com/zudolab/zudo-doc/issues/4469), which records the two selector updates. Keep `.zd-home-copy` as an authored class: `src/content.css:547` styles it and `src/theme-packs/academia/pack.css:176` selects it. Please include `.zd-home-copy` in #4440's authored-class manifest/coverage set. `.zd-wrap-anywhere` remains because `src/features.css:1311` ships its `overflow-wrap` rule.
- The unsupported `rounded-l` utility on `AssetDetailsToggle` was replaced with `border-top-left-radius` and `border-bottom-left-radius` set to `var(--radius-DEFAULT)`; `src/theme.css:113` defines this as `0.25rem` (4px), matching the former `rounded-l-DEFAULT` intent. No no-op rule was added. `ease-in-out` remains backed by the authored theme token.
- Port tests are source-resolution tests. Test-only zudo-react seams prevent the current red-window shared head/layout and scanner-owned identities from being pulled into these component checks; the home intro seam renders the prepared serializable fixture nodes so route preparation and page composition remain asserted. The seam does not claim the adjacent `#4457`/`#4458` implementations' full output.
