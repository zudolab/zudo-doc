## Pending first-activation cross-case diagnostic

The extended browser run passes unchanged, changed props, host preserve,
structural replacement, and a distinct authored component identity (five cases).
Its pending visible skip-SSR case fails: after the changed-props SPA hop the
never-activated island has one activation, even though its top remains
2097.875px in a 720px viewport and scrollY remains zero. Diagnostic suite result
is **8 passes / 1 failure**, preserved with raw before/after attributes, geometry,
label, reservation and public lifecycle counters in the control directory.
Direct pending-b and fresh nonpersisted navigation stay deferred; a native
persisted route with no zudo-doc helper also mounts early. This separates the
native published behavior from consumer helper preparation and viewport changes.

Published runtime source explains a candidate cause: a changed persisted pair
gets a remount flag, clearMountedForRemount returns true without checking for a
previous handle, and the force branch fires before consulting data-when.
[Upstream #1432](https://github.com/Takazudo/zudo-front-builder/issues/1432)
requires ordinary first-time deferred hydration to stay deferred and limits
scheduler bypass to replacements of already-mounted roots;
[#3420](https://github.com/Takazudo/zudo-front-builder/issues/3420) introduced
nested changed-pair classification without explicitly covering this intersection.
This is a measured native cross-case discrepancy, not an authorized consumer
shim or upstream implementation task. A standalone exact published4.2.1 fixture
without zudo-doc/workspace links is prepared under the archived
native-published-repro directory; its manager result is **2 passes / 1 failure (3.5s)**, guard FAIL (5s).
Direct-load and nonpersisted controls pass; the persisted strict expectation
remains zero but observes one. Registry manifest/lock and raw attachments are
archived. Both probe ports were free after exit. The focused upstream issue
and disposition remain pending; no upstream code or consumer repair is applied. Existing permanent hosted E2E passes461 but does not close this
new explicit pending-activation control or certify whole #4468 parity.
