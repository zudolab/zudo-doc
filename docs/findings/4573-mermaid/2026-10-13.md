# Mermaid browser delivery candidate — 2026-10-13

UNRELEASED; real CDN acceptance remains required. The default browser URL changes
from `https://esm.sh/mermaid@11.15.0` to `https://esm.sh/mermaid@11.17.2`.
Neither the root nor framework manifest declares a local Mermaid dependency.
Published zudo-doc 6.1.1 still contains the old URL. This change does not publish
packages or remediate that already published artifact.

## Upstream review

The npm package is **mermaid**, not the monorepo's independently released tiny
package. The published 11.17.2 tarball was downloaded and inspected. Its integrity
is `sha512-V6K3C8EBdEsPFZXSKMJe6ppQOENxuHARr9GvHX4hh47lAbhMRD9qf4oEK7LoaRQxULMa80/qt5gHO73aCleBBg==`.
Its ESM/default export remains `dist/mermaid.core.mjs`, with a default object
exposing `initialize` and `run`, as the existing inline loader uses. No local
package dependency, public export, custom URL restriction, security option,
render lifecycle or color conversion is changed.

The five issue advisories were refreshed from upstream. Their patched 11.x
floor is 11.16.1 (11.15.0 is affected):

- [Configuration prototype pollution](https://github.com/mermaid-js/mermaid/security/advisories/GHSA-c4c3-pg64-4m4v): affected 11.0.0-alpha.1 through 11.16.0. Upstream distinguishes trusted configuration APIs from already protected authored diagram configuration.
- [CSS sibling injection](https://github.com/mermaid-js/mermaid/security/advisories/GHSA-6x64-9x62-f2gx): affected 11.0.0-alpha.1 through 11.16.0.
- [Architecture prototype pollution](https://github.com/mermaid-js/mermaid/security/advisories/GHSA-3rrr-jr9j-h3q3): affected 11.5.0 through 11.16.0.
- [XY chart denial of service](https://github.com/mermaid-js/mermaid/security/advisories/GHSA-2v8p-3f2j-5mp7): affected 11.0.0-alpha.1 through 11.16.0.
- [Radar denial of service](https://github.com/mermaid-js/mermaid/security/advisories/GHSA-rhh3-jpg6-66xh): affected 11.6.0 through versions below 11.16.1.

The [upstream advisory index](https://github.com/mermaid-js/mermaid/security/advisories)
showed those August 4 advisories as its newest entries at inspection. This is
version remediation, not proof of an exploitable application path or a complete
security audit.

[11.16.1](https://github.com/mermaid-js/mermaid/releases/tag/mermaid%4011.16.1)
contains the five fixes and deprecates `mermaidAPI.setConfig` (unused here).
[11.17.0](https://github.com/mermaid-js/mermaid/releases/tag/mermaid%4011.17.0)
changes the class/C4 renderer, adds flowchart shapes and uses fastdom for DOM
measurement. [11.17.1](https://github.com/mermaid-js/mermaid/releases/tag/mermaid%4011.17.1)
fixes C4 wrapping and diagram markers.
[11.17.2](https://github.com/mermaid-js/mermaid/releases/tag/mermaid%4011.17.2)
restores the `edgePaths` SVG class and associated styles. The candidate stays
on stable 11.x; npm's newer 12.x major is outside this bounded change.

## Remote dependencies

The tarball declares KaTeX `^0.16.47`, DOMPurify `^3.3.3`, stylis `^4.3.6`,
parser `^1.2.1`, khroma `^2.1.0` and fastdom `1.0.12`, among other dependencies.
The range declarations do not prove the versions or bytes esm.sh actually
serves. The remote KaTeX copy is independent of zudo-doc's optional local peer
and held PR #4576. A root npm audit cannot certify this browser dependency graph.

The environment's direct CDN probe was denied at CONNECT (HTTP 403), including
the supported escalated request. No alternative proxy, stub, or network bypass
was used. Until a normal browser successfully requests the exact candidate and
renders genuine SVG, browser acceptance and remote graph inspection are
unverified. Failed network loading is not a passing rendering assertion.
