# A2 causal review: ZFB 5.1.2

The accepted reference is the one PR #4640 set for ZFB 5.1.1. Its native build identity is `3ce404177026a463`.

## Candidate capture

The candidate is a local `ZUDO_A2_CAPTURE_DIR` capture of PR #4641's bump commit (`44d7684b9d349ef8e5302b865956e44348dfc548`), run with the same `A2 no-stub` test the PR Checks A2 job runs. For #4640, a local capture of the PR head was byte-identical to the hosted CI capture on all three normalized pages, so the local capture stands in for the CI one here.

Only the three strict fingerprints failed.

## Comparison

- **Lengths:** in 404, getting-started and coverage order, the raw candidate pages are 57,025, 67,457 and 78,909 bytes, the same as the 5.1.1 candidate.
- **Build identity:** the pages carry 1, 2 and 4 `data-zfb-build` values respectively. Every one changes from `3ce404177026a463` to `5bf32a885b3810b8`.
- **Residual:** substituting only those attribute values back to `3ce404177026a463` makes every normalized candidate page hash to the accepted 5.1.1 reference. No other byte differs.

## Cause

The bump moves the ZFB family (`zfb`, `zfb-runtime`, `zfb-md-wasm` and `zfb-adapter-cloudflare`) from 5.1.1 to 5.1.2. Those package versions are inputs to the native build identity. The published 5.1.2 tarballs change only version pins and rebuilt native and WASM binaries; the JavaScript surface is unchanged.
