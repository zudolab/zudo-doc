# zudo-doc-online-worker

Private workspace package (epic zudolab/zudo-doc#3361): a Cloudflare Worker
(Hono + D1) that becomes the future remote backend for
`packages/zudo-doc-online/`. Not published to npm.

## Role

The local API server in `packages/zudo-doc-online/` (port 4324) stays
auth-free — local authoring is unaffected by anything in this package. This
worker exists only toward the eventual remote path: authenticated multi-user
access to a zudo-doc-online project store, fronted by Better Auth
(email/password + bearer tokens). The `/api/auth/*` routes themselves are
not mounted yet (a later sub-issue) — this package currently only carries
the Better Auth foundation: pinned deps, the generated schema, tracked D1
migrations, and a vitest D1 bootstrap.

## Commands

- `pnpm --filter zudo-doc-online-worker dev` — `wrangler dev`, default port
  8787
- `pnpm --filter zudo-doc-online-worker deploy` — `wrangler deploy`
- `pnpm --filter zudo-doc-online-worker typecheck` — `tsc --noEmit`
- `pnpm --filter zudo-doc-online-worker test` — `vitest run` under
  `@cloudflare/vitest-pool-workers` (frozen test-harness choice — do not
  substitute miniflare directly). Runs standalone and as part of the root
  `pnpm test`'s `test:packages` step. Applies the tracked `migrations/`
  against the ephemeral test D1 database before any suite runs (see
  `vitest.config.ts` / `src/__tests__/setup/apply-migrations.ts`).
- `pnpm --filter zudo-doc-online-worker db:migrate` — `wrangler d1
  migrations apply zudo-doc-online-db --local`. Idempotent, version-tracked
  (not a `d1 execute` loop). Run once before `pnpm dev` on a fresh clone.
- `pnpm --filter zudo-doc-online-worker run auth:generate-schema` —
  regenerates `src/auth-schema.ts` from the live `createAuth` config. See
  that file's own header comment before touching it by hand.

## Architecture

```
src/
├── index.ts          # Hono app — CORS, GET /api/health, error mapping
├── cors.ts           # CORS allowlist constant for the SPA's dev origin (4323)
├── auth.ts           # createAuth(env) — per-request Better Auth factory
├── auth-schema.ts     # GENERATED drizzle schema — see its header, do not hand-edit
└── __tests__/        # vitest-pool-workers suites + D1 migration bootstrap
scripts/
└── better-auth-cli-config.ts  # config the schema-generation CLI runs against
migrations/
└── 0001_better_auth.sql       # tracked SQL, hand-derived from auth-schema.ts
```

- `wrangler.toml` — `nodejs_compat` compatibility flag (Better Auth imports
  `node:crypto`), and a `[[d1_databases]]` binding `DB` against
  `zudo-doc-online-db` with a placeholder `database_id` (same placeholder
  convention as `packages/search-worker`'s KV id — replace it after
  `wrangler d1 create` when actually deploying).
- `src/auth.ts` builds a Better Auth instance **per request** via
  `createAuth(env)` — D1 bindings are request-scoped in Cloudflare Workers,
  so a module-scope instance would capture a stale/undefined binding. There
  is no module-scope `betterAuth(...)` call anywhere in this package.
  `trustedOrigins` is derived from `src/cors.ts`'s `CORS_CONFIG.origin`
  rather than duplicated, so the CORS allowlist and Better Auth's origin
  check can't drift apart. Only the `bearer()` plugin is enabled so far.
- `src/auth-schema.ts` is generated by the Better Auth CLI (npm package
  `auth`, not the deprecated `@better-auth/cli`) run against
  `scripts/better-auth-cli-config.ts`, which calls the real `createAuth`
  factory with dummy env values — the schema can never drift from the live
  plugin set. `migrations/0001_better_auth.sql` is a hand-derived, tracked
  SQL rendering of that schema (plain `CREATE TABLE`/`CREATE INDEX`, no ORM
  migration engine).
- Vitest bootstrap: `vitest.config.ts` reads the tracked migrations via
  `readD1Migrations()` (Node-side) and passes them into the worker as the
  `TEST_MIGRATIONS` binding; `src/__tests__/setup/apply-migrations.ts`
  (a `test.setupFiles` entry, runs inside the worker) applies them via
  `applyD1Migrations()` before any suite executes. `src/__tests__/env.d.ts`
  augments the ambient `Cloudflare.Env` type with this worker's bindings —
  extend it there, not by casting `env` inline. `schema-parity.test.ts`
  asserts every table/column in `auth-schema.ts` exists in the migrated
  test database, so a stale migration fails loudly even in paths the auth
  flow itself wouldn't exercise.
- Response format: `{ error: { code, message } }` for routes this worker owns
  directly (e.g. `/api/health`). Future `/api/auth/*` routes mounted from
  Better Auth keep Better Auth's own response format — they are NOT forced
  through this mapping.
- CORS: origins `http://localhost:4323` / `http://127.0.0.1:4323` (the SPA's
  Vite dev origin), `credentials: false`, and `exposeHeaders:
  ["set-auth-token"]` so browser JS can read the future bearer-session
  response header.
- `.dev.vars.example` documents the two local env vars (`BETTER_AUTH_SECRET`
  name-only, `BETTER_AUTH_URL` with its local value). The real `.dev.vars`
  is gitignored at the repo root (`packages/*/.dev.vars`). Production setup
  (D1 create, `wrangler secret put`, prod URL) is a deliberately manual
  operator step — see `README.md`.
